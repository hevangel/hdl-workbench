# LUNA-00B: Surfer browser integration feasibility**Status: browser proof passed for the pinned Surfer v0.7.0 build.** The same-origin iframe loaded the real counter VCD through both an HTTP URL and a Blob URL. The tested `InjectMessage` payloads added `top.count` and moved the visible cursor to 25 ns. The screenshots and complete browser log are checked in with the spike. The inner message API remains explicitly unstable upstream, so keep it behind a versioned adapter.## Pin, license, and build output| Item | Result ||---|---|| Upstream release/source | Surfer `v0.7.0`, commit `bd749b1f786c1c62cd67893ca71346cbe6983915` || License | EUPL-1.2; upstream license is included at `spikes/surfer-embed/assets/LICENSE-EUPL-1.2.txt` || Rust/Cargo | `rustc 1.99.1 (58cf8f9c3 2026-10-13)`, `cargo 1.99.1 (5f94df478 2026-08-27)` || Target and Trunk | `wasm32-unknown-unknown`; Trunk `0.21.14` (the version in pinned CI) || Pinned submodules | `f128` `e60de395f0d6454c1dc546b87f06a6358425b6b6`; `instruction-decoder` `02bdcbfd5663a72e4a0b1b9d54519412d417fab1` || WASM SHA-256 | `1341ad01c59f5169209239728417d14f430183abd92515f22bf07cd7c86937ae` || Complete asset digests | [`spikes/surfer-embed/assets/SHA256SUMS`](../../spikes/surfer-embed/assets/SHA256SUMS) |The source clone initially lacked submodules; `cargo metadata` failed with `no matching package named f128 found`. The generated asset checksum manifest pins the resulting files, including the custom iframe HTML.## Verified host integrationThe pinned [`surfer/assets/integration.js`](https://gitlab.com/surfer-project/surfer/-/blob/bd749b1f786c1c62cd67893ca71346cbe6983915/surfer/assets/integration.js) listens for `window.postMessage` and supports these wrapper messages:- `LoadUrl`: `{ "command": "LoadUrl", "url": "..." }`; the wrapper sends `LoadWaveformFileFromUrl(url, Clear)` to Surfer.- `InjectMessage`: `{ "command": "InjectMessage", "message": "<serialized Rust Message>" }`; the wrapper forwards the inner message to Surfer's `inject_message` function. Upstream marks this inner message API unstable.The browser test used these pinned-build inner payloads:```json{"AddVariables":[{"path":{"strs":["top"],"id":"None"},"name":"count","id":"None","index":null}]}``````json{"CursorSet":[1,[25]]}```The add-variable object matches `VariableRef` / `ScopeRef` Serde types in the pinned source. Cursor uses the pinned `BigInt` Serde tuple: positive sign `1` plus little-endian base-2^32 digits `[25]`. These shapes were **observed working in this build**, not adopted as a stable cross-version API.The iframe sends a ready event from the upstream-documented `SURFER_SETUP_HOOKS` placeholder after the WASM module initializes. The parent test then sends the wrapper messages to the iframe with the exact same origin. The harness serves the parent page, local Surfer bundle, and VCD from one origin.## Browser test and evidenceAutomated test: [`spikes/surfer-embed/test_surfer_integration.py`](../../spikes/surfer-embed/test_surfer_integration.py), executed with Python Playwright `1.59.0` and Camoufox `0.4.11` under Xvfb. Test Chromium and at least one supported production Firefox version before release.- The WASM build logged a `ThreadPoolBuildError` (`operation not supported on this platform`) during asynchronous wave work in this container. The 80 ns fixture still loaded, rendered, and accepted signal/cursor messages; large-waveform performance and worker behavior remain untested.- Headless Camoufox without WebGL crashes with `WebGL isn't supported`; headed Firefox under Xvfb passed. The test command intentionally uses `DISPLAY=:99` and `--headed`.- Rust WCP functions exist in source, but the pinned Trunk glue does not expose them to the parent page. This spike does not validate a browser WCP bridge.- Freeze the adapter only around the documented wrapper and the tested v0.7.0 inner payloads.
